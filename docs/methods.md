# Evaluation methods

Choose the lightest method that resolves the doubt. Every method costs the candidate and the reviewer time. Use the primary method for the role, and add a heavier one only when the panel has written down a specific question it must answer.

● primary method for the role · ○ optional, only for a named doubt · – not used

| Method | Intern | SE | SSE | TL | Architect | Candidate time |
| --- | :-: | :-: | :-: | :-: | :-: | --- |

| Live coding / pair programming | ● | ● | ○ | – | – | 20–60 min |

## Method guide

| Method | What it reveals | Watch out for | Template |
| --- | --- | --- | --- |
| Live coding / pair programming | Clarifying, fluency, testing habit, collaboration | Nerves; keep the task small and clear | [Feedback form](kit/feedback-form.md) |
| Take-home assignment | Code quality, structure and tests in a calm setting | Unpaid time and AI help; always review it live | [Assignment brief](kit/assignment-brief.md) |
| Case study | Ambiguity handling, business-rule reasoning, delivery habits over days | Heavy; strong people with jobs drop out. Default to Core (1–2 days) | [Assignment brief](kit/assignment-brief.md) |
| Proof of concept | Learning speed, judgement on unknowns, honest reporting of limits | Never real client work; cap at 3 days | [POC brief](kit/poc-brief.md) |
| System design interview | Data modelling, failure handling, scale, cost, trade-offs | Generic "design Twitter" problems reward memorised answers | [Design exercise](kit/system-design-exercise.md) |
| Code review exercise | Quality bar, security and failure awareness, how they give feedback | Plant issues of different severity, not only style | [Code review guide](kit/code-review-exercise.md) |
| Leadership scenario | Prioritisation, communication, people handling, honesty with clients | Probe what they did in real situations, not only the plan | [Leadership scenario](kit/leadership-scenario.md) |
| Architecture portfolio and kata | Breadth, trade-offs, cost, security, migration, influence | Polished slides can hide shallow ownership; ask about regrets | [Architecture brief](kit/architecture-presentation.md) |
