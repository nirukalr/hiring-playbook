# Software Engineer

About 2 to 4 years. Owns well-defined features end to end within an agreed design.

**Candidate time:** about 4 hours · **Decision:** within 21 days

## What we look for
- Builds, tests and ships features without hand-holding
- Writes readable code and tests the business rules
- Handles the common failure cases: bad input, retries, timeouts
- Asks clarifying questions before writing code

**Must-haves:** technical depth; code quality and testing; ownership and delivery.

## Panel
Project tech lead (hiring lead) plus one independent SSE or above from the interviewer pool. One project engineer for the team interview.

## Stages
| Stage | Format | Time | Who |
| --- | --- | --- | --- |
| Technical interview | Intro (5), deep-dive (25), what-if challenge (15), role scenario (15), coding check (10), questions (5) | 75 min | Hiring lead + independent |
| Evaluation exercise | Pair programming on a small realistic feature, or a take-home of 4 hours or less with a 30-min review | 60 min | Project engineer + hiring lead |
| Team interview | Engineers describe a real ticket; the candidate asks questions and plans the approach | 45 min | Project engineers |
| HR culture interview | Structured values interview | 45 min | HR |

## Sample questions
- "Walk me through a feature you built. Where does the data live, and what happens when the API call fails?"
- "What if this request is sent twice?"
- "How did you test it, and what did you not test?"
- "Tell me about a requirement that was unclear. What did you do before coding?"

## Red flags
- Only describes the happy path
- Testing is "QA's job"
- Cannot separate their work from the team's
